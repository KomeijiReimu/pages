# 打开一万行代码的笔记：Quartz 长文阅读优化记录

这项改动起于一次几乎读不下去的桌面体验：点开一篇带大量代码的笔记，页面长时间不响应，连鼠标移动都显得断断续续。调整窗口大小、打开开发者工具改变视口时，卡顿还会重现。当时没有系统级性能记录；后来能用同一份笔记反复测量的，是浏览器在打开页面时创建了多少元素、主线程被占用了多久，以及跳到远处能否立刻读到代码。

本站基于 Quartz 4.5.2。现在，读者打开笔记就能看到完整源码和行号，浏览器只给眼前的代码着色。做到这一点经历了几步：先减少离屏排版，再减少首屏要创建的元素，最后把读位、行号和源码从高亮任务中独立出来。

## 为什么建站时已经上了色，打开文章还会卡

一行 `const value = 42` 可以作为一段文本交给浏览器，也可以把关键字、变量、运算符和数字各自包进带样式的 `span`。Quartz 在构建时算出颜色；浏览器打开文章时，仍要解析这些标签、创建 DOM 元素、计算样式和排版。在一篇有几百个代码块的笔记里，读者只看第一屏，浏览器却可能已经为整篇创建了几万个元素。

2026 年 11 月 23 日核对的上游稳定版是 [Quartz 5.2.2](https://github.com/jackyzha0/quartz/releases/tag/v5.2.2)。[默认配置](https://github.com/jackyzha0/quartz/blob/2386362d5716503007c1fec1ea362204ee711f13/quartz.config.default.yaml) 使用构建期语法高亮插件；普通站内链接仍由 [SPA 路由](https://github.com/jackyzha0/quartz/blob/2386362d5716503007c1fec1ea362204ee711f13/quartz/components/scripts/spa.inline.ts) 取回目标 HTML，再用 micromorph 比较、更新页面。从地址栏直接打开文章，只承担前一笔 DOM 成本。从目录点进去，还要承担新旧页面的比较开销。

用这个版本的默认配置和锁定的高亮插件 1.0.3 构建一篇合成笔记：275 个 TypeScript 代码块，每块 38 行，内容形如 `const v0_0 = 0 + 0`。生成的 HTML 为 6,232,421 字节，里面已有 10,450 个高亮行元素、62,700 个带样式的词元元素，整个文档共 74,122 个元素。上游 5.2.2 仍把这一整套元素交给浏览器。这里统计的是构建产物；下节的浏览器耗时来自本站的对照实验。

## 先减轻排版，再减少元素

2026 年 5 月，第一步是在构建时统计代码行数，给离屏代码块预留高度，用 `content-visibility` 让浏览器跳过暂时看不见的内容。同一次改动还改了复制按钮：过去进入笔记就为每一块准备复制文本，缺少预存源码时读取 `innerText`，可能迫使浏览器当场计算布局。现在点哪一块才读取哪一块。只阅读、不复制，就省下了整轮取文本的工作（`1db80c8`）。

离屏内容可以暂缓排版和绘制，HTML 中的高亮标签仍然要变成 DOM。接下来的两次改动把代码块先输出成纯文本，把颜色留到靠近视口时再补，每次约 12 行（`6c0d438`、`a9201ca`）。站内导航也按页面体量分流：小页沿用 SPA；中大型页面直接替换 `#quartz-root`，跳过整页逐节点比较和大正文入场动画；再大的页面交给浏览器原生打开（`62029b4`）。

下面是本站相同主题、相同笔记的渲染对照。样本有 275 个代码块，每块 38 行，共 10,450 行。桌面 Chromium 153，视口 1280 × 800，CPU 降速 4 倍；每种方式各测三轮。耗时列统计首次内容绘制后 3 秒内，每个主线程长任务超过 50 毫秒的部分，取三轮中位数。

| 同一份高亮结果怎样显示             | 页面元素 | 长任务超出 50 毫秒的时长合计 |
| ---------------------------------- | -------: | ---------------------------: |
| 一次展开全部高亮，离屏允许跳过绘制 |   74,728 |                   约 2.27 秒 |
| 按视口分片挂载（`adecd5b`）        |    4,602 |                   约 0.97 秒 |

第一种方式比第二种多创建约七万个元素。表中时间是多个任务的合计；最初观察到的鼠标顿挫没有系统帧率记录。

## 跳到文章深处，先看到字

早期的极长页优化会把远离视口的代码块清空，只保留高度占位（`5cc9f9a`）。这对逐屏滚动有效，却给跳读留下了问题：在 275 块的样本里，直接跳到第 173 块，位置已经到了，眼前约 995 像素高的区域还是空的；一次实测等了 4.70 秒才出现源码。浏览器后退也会遇到同样的问题：恢复了滚动坐标，却没恢复那几行字。

`ce4297f` 让每一块始终保留服务端输出的纯文本，离屏只回收着色元素。按行高和上下内边距预留空间，块进入视口时就不必重新挪动下面的正文。暂停浏览器所有空闲任务，再跳到同一位置，集成测试在第 2 帧（约 25 毫秒）看到源码和行号，当时整页还没有一个高亮行元素。离开再后退，滚动坐标前后都是 173,417 像素，视口第一行也一致。

行号原先画在每个高亮行的伪元素上，颜色没来时，行号也不见了。`5fad083` 把它改成和源码一起横滚的独立编号列。在桌面 1280 像素和手机宽度 390 像素下打开同一个 1,201 行代码块，首次着色前，行号列就已从 98 编到 1298；复制、选择源码不会带上行号。第一次着色只创建当前 12 行的高亮元素，随后从读者所在位置继续。单块 2,600 行的样本直接跳到第 1,950 行，1.8 秒时眼前的代码已着色，整块只有 108 个高亮行元素。

这轮修复改善的是跳读和返回时的空白。连续滚动另做了窄屏对照：390 像素宽、4 倍 CPU 降速、4 秒滚过 16,000 像素，新旧版帧间隔中位数都约 16.7 毫秒。这里的手机宽度来自 Chromium 模拟。

## 把高亮数据从首份 HTML 移开

按需创建 DOM 之后，颜色数据仍然随 HTML 一次下载。本站最早用来分析文档大小的 275 × 38 行样本有 6,687,850 字节，其中 5,733,399 字节（85.7%）是序列化高亮。读者只看文章开头也要下载、解析整份文档。

现在构建时给每篇笔记的内联高亮数据留出 128 KiB。超过预算时，优先把最大的块拆成独立 JSON；每份最多包含 8 个分片、96 行，上限 64 KiB。文件名由内容的 SHA-256 决定，同样的高亮只写一份。浏览器读到相关代码时才取相应文件。高亮数据未超过预算的笔记仍将其内联，不增加请求。没有 JavaScript、请求失败，或某个 12 行分片单独就超过上限，读者看到的都是原来的源码和行号。

用与上游复现相同的代码行，在本站构建 `/notes/lab/many`，保持输入和页面布局一致。以 `164077d` 为基线，首份 HTML 从约 6.72 MB 降至 0.91 MB（减少约 86%），Node 默认 gzip 压缩后从约 207 KB 降至 128 KB（减少约 38%）。268 个代码块的高亮数据移到了独立文件，合计 4.58 MB；它们留在站点上，按阅读位置下载。嵌入这篇笔记的页面复用同一批文件，小笔记没有外置高亮。

构建还会根据最终 HTML 的大小标记需要原生打开的目标。站内链接和悬停预览共用这个判断，避免先把超大文档当预览或 SPA 内容取回，再让浏览器下载一次。缩小到阈值以内的页面继续用原有的导航方式。

## 怎样复查

**复现上游输出。** 在 [5.2.2 的源码目录](https://github.com/jackyzha0/quartz/tree/2386362d5716503007c1fec1ea362204ee711f13) 用 Node 24.19.0、npm 11.17.0 运行 `npm ci`，保留发行版默认配置。下面的命令生成测试用的 `fixture/index.md`（250,459 字节，UTF-8、LF），并构建页面：

````sh
mkdir fixture
python3 - <<'PY'
from pathlib import Path
blocks = ['```ts\n' + '\n'.join(f'const v{b}_{r} = {b} + {r}' for r in range(38)) + '\n```' for b in range(275)]
Path('fixture/index.md').write_bytes(('---\ntitle: Synthetic TypeScript fixture\n---\n\n' + '\n\n'.join(blocks) + '\n').encode())
PY
node ./quartz/bootstrap-cli.mjs build -d fixture -o out-full
````

测量对象是未压缩的 `out-full/index.html`。用 parse5 8.1.1 解析该文件，统计整棵文档树的元素，不计文本节点和注释；代码区分别数 `pre code [data-line]` 和这些行内的 `span[style]`。这样不会把浏览器运行脚本后新增的元素算进构建结果。

**复查本站的阅读体验。**

[`scripts/verify-code-gutter.mjs`](../../scripts/verify-code-gutter.mjs) 会生成合成笔记、构建站点，再用 Chromium 检查首次高亮前的行号像素、复制结果、横向滚动和离屏恢复。安装仓库依赖后，指定本机 Chromium 和 `puppeteer-core` 的入口文件：

```sh
CHROME_BIN=/path/to/chromium \
PUPPETEER_MODULE=/path/to/puppeteer-core.js \
node scripts/verify-code-gutter.mjs
```

复查打开瞬间的工作量，可在浏览器性能面板中分别记录直接打开和从目录进入，固定视口、CPU 降速与缓存设置，对照首屏元素数、长任务和文档请求。复查阅读则保留两个动作：从文章顶部跳到远处，检查高亮尚未完成时能否选择、复制源码；从那里打开另一篇，再后退，核对视口第一行。同一个滚动坐标和一块正确高度的空白占位，都不能代替读者要看的那行代码。
